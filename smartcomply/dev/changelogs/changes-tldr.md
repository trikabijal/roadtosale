# What Changed (10-second read)

- **One `.gitlab-ci.yml`** across all branches. `build` runs **automatically only on `devops`**. On every other branch (kazi-development, development, main, fix/*, MRs) it's a **manual play button** — click it from the Pipelines UI when you want to validate. `package` + `deploy` still run on **devops only**.
- **`application.properties` is now identical on every branch** (env-agnostic). Env-specific stuff lives in `application-{profile}.properties`.
- **No more `spring.profiles.active=` in `application.properties`.** Set it externally: deploy uses `-e SPRING_PROFILES_ACTIVE=uat`. Local devs set their own.
- **AI keys** (`ANTHROPIC_KEY` / `OPENAI_KEY` / `GEMINI_KEY` / `GROK_KEY`) are masked GitLab CI variables, injected via `docker run -e` at deploy.
- **AI is on for UAT, off everywhere else** (lives in `application-uat.properties`).
- **Two manual seed jobs** on the devops pipeline — click Play any time the UAT DB needs reseeding: `seed-kia-uat-users` (10 users), `seed-kia-dealerships` (627 dealers, 1,154 locations).
- **New entity `Region`** + `states.region_id` + `auditees.phone/email/website`. V1.23 migration adds them to existing UAT and creates BI indexes. NOT NULL on `region_id` is JPA-only for now (UAT can't enforce until all states have a region — V1.24 follow-up).
- **V1.27 — Interventions (Improvement Campaigns).** New `interventions` + `intervention_assignments` + `intervention_assignment_questions` + `intervention_assignment_targets` tables, parallel to `audits` + `audit_assignments`. `user_checksheets` reused for re-inspection waves (parent FK is `intervention_assignment_id` instead of `audit_assignment_id`; CHECK constraint enforces exactly-one-parent). The old `re_audits` table and parallel service were deleted in this refactor. Endpoints under `/api/intervention` and `/api/intervention-assignment`. New permissions `INTERVENTION_MANAGE` / `INTERVENTION_ASSIGNMENT_VIEW` / `INTERVENTION_ASSIGNMENT_MANAGE` / `INTERVENTION_ASSIGNMENT_ACKNOWLEDGE` / `INTERVENTION_CONDUCT` and a new role `DEALER_PRINCIPAL`. `audit_signal` CTE's `pct_ok` LATERAL extended to roll up post-intervention current state — every BI panel inherits the lift automatically. See [`system-overview.md`](./system-overview.md) and [`test-plan-intervention.md`](./test-plan-intervention.md).
- **V1.28 — Inspections collapse.** Three runtime tables (`audit_assignments` + `intervention_assignments` + `user_checksheets`) merged into a single `inspections` table with a `kind` discriminator (`AUDIT` | `INTERVENTION`). Child tables kept their pre-V1.28 names but their FK column was renamed `user_checksheet_id` → `inspection_id`. Status enum: ASSIGNED → IN_PROGRESS → SUBMITTED → VALIDATED → APPROVED, with DECLINED bouncing back.
- **Audit-report authorization hole closed.** `POST /api/userChecksheet/getUserChecksheetWithAnswers` previously had NO authorization check — any authenticated user could read any UC's full content + photos by changing the id in the request body. Now gated by a shared `assertUserChecksheetVisible` rule: caller must have `AUDIT_VIEW` perm, OR be the operator who filled the UC, OR be the Dealer Principal of the UC's dealership. The two sibling endpoints `GET /api/audit/userChecksheetMeta` and `GET /api/audit/userChecksheet/{id}/improvement-overlay` were widened to allow operator + DP (previously the overlay was AUDIT_VIEW-only, blocking operators from seeing their own work).
- **New endpoint `GET /api/intervention/audit/{auditId}/claimedQuestions`.** Returns the set of `chksQuestionId`s already covered by another ACTIVE or DRAFT intervention for that audit, with the claiming campaign's `{id, name, priority, status}`. The "New Intervention" form uses this to hide already-claimed questions from the picker and render a banner naming the claiming campaign(s) — replaces the previous "Save & Activate" → generic 409 error path.
- **Audit-report `getImprovementOverlay` fully implemented.** Was stubbed for V1.28 (returning empty `questionFlags`, `reAuditAnswers`, `headerSnapshots`). Now returns the per-question intervention flags, the temporal chain of re-inspection answers (with attribution + comment + photo URLs), header snapshots per intervention, and `originalScore` / `currentScore` / `scoreDelta` rolled up via the same audit-signal CTE.
- **New design doc: [`role-flows.md`](./role-flows.md)** — landing pages + primary-action minimum-click paths for all 10 roles (Auditor → Audit Validator → Audit Approver → Manager → Dealer Principal → HoDD → Audit & Intervention Builder → Template Creator/Validator/Approver), ordered by sessions-per-year per individual. Includes a "Shared screen: Audit Detail" section describing the proposed `/campaigns/audits/:auditId` page (Locations + Interventions + BI tabs) and a "Build sequencing" recommendation.

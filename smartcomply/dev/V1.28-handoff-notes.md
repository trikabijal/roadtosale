## Architectural decisions baked in

1. **Multi-wave re-inspection NOT supported.** One inspection per
   (audit-or-intervention, location). If a re-inspection cycle needs
   to repeat, create a new intervention. Hard-fail in the migration
   if multi-wave data exists.

2. **No ACKNOWLEDGED status, no NON_COMPLIANT status.** Per user:
   acknowledged is a future flow, non-compliant is a derived state
   based on per-tenant compliance thresholds (not stored).
   Status enum: ASSIGNED | IN_PROGRESS | SUBMITTED | VALIDATED |
   APPROVED | DECLINED.

3. **Compatibility shims on Inspection** — `getAuditAssignment()`,
   `getInterventionAssignment()`, `setAuditAssignment(...)`,
   `setInterventionAssignment(...)` all return / use `this`. Lets
   existing callers `inspection.getAuditAssignment().getAudit()`
   compile and behave correctly. Plan: remove the shims when the
   call-site cleanup pass happens.

4. **Class names like `UserChecksheetServiceImpl`,
   `UserChecksheetController` kept** — the noun rename across
   service / controller / DTO layer is bigger than the entity rename
   and was deferred. Filed as GitLab #19 (combined with Bucket A+C).
